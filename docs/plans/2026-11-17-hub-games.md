# Games for the hubs' machines (design note, 2026-11-17)

The owner, 2026-11-17: "what can we do to make new cabcrawl and tracker games go to the archive when either of [them] gets new
games? I'd prefer to not go to the archive as much as possible." Her OK on the plan below came the same day ("Let's do both").

## What already existed

- Each app's machine (cabcrawl `Game.model_key`, the tracker's `Asset.model_key`) names its game in the library by key, and the
  key reaches the deck in each hub's roster (contract v1's `model_key`), cached by `gatbox-sync` every two minutes.
- The apps read the archive every ten minutes for the keys their machines name, and follow a retired key (`replaced_by`) to its
  survivor (library-v1's read contract; both apps do).
- What was missing: a key the library hasn't got went nowhere, and a new machine had no key unless a manager typed one.

## The design

**On the deck (`backend/gatboxweb/hubgames.py`):**
- Every minute, and whenever LIBRARY loads, each hub key that names no game in the library is looked at.
- A plainly new key: the deck makes the game itself, titled from the machine's name (a cabinet number on the end, " #2", left
  off), kind video, a note saying which hub's machine list it came from. The library sync takes it to the archive; the apps' next
  read finds it.
- A key that reads like a game the library has (the titles or keys match once case, "&"/"and", "the", punctuation and Roman
  numerals II-X are set aside): nothing is made. It waits on the 7" under LIBRARY → FROM THE HUBS (N):
  - **SAME AS <game>**: the hub's key is kept as a retired key with `replaced_by` that game. The apps already follow it.
  - **ADD AS NEW**: the game is made after all.
  The answer is kept in gatbox-web's state (`hub-games.json`) so it isn't asked again.
- A key that isn't a valid key, and a machine with no key, are left alone.

**In each app:** a machine added with no key gets one from its name (the tracker: from the Model field when filled, machines
only), by the library's own slug rule, the cabinet number left off. It is an ordinary field: a manager changes it like any other.

## Not done

- Machines that existed before have no key unless someone set one (cabcrawl has `scripts/link_model_keys.py`).
- A game made from a machine's name has only a title. Its maker and year are added with EDIT GAME on the 7" (or on the archive).
